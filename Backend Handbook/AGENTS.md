# Backend Interview Bible 프로젝트 운영 규칙

> 이 문서는 Backend Interview Bible 프로젝트의 운영 규칙을 정의합니다.
>
> Codex 또는 AI는 문서를 생성하기 전에 반드시 이 문서를 먼저 읽고 따라야 합니다.

---

# 1. 프로젝트 목적

Backend Interview Bible은 Java 백엔드 개발자를 위한 실무 중심 기술 핸드북 프로젝트입니다.

이 프로젝트의 목표는 다음과 같습니다.

- Java 백엔드 핵심 기술 정리
- Spring 생태계 정리
- 운영 환경(Production) 경험 정리
- 시스템 설계(System Design) 학습
- 기술 면접 대비
- 지속적으로 성장 가능한 기술 문서 구축

문서의 개수를 늘리는 것이 목적이 아닙니다.

모든 문서는 프로젝트 전체의 품질을 높이는 방향으로 작성되어야 합니다.

---

# 2. AI의 역할

AI는 단순히 문서를 생성하는 도구가 아닙니다.

다음 역할을 수행해야 합니다.

- 새로운 문서 작성
- 기존 문서와 중복 여부 확인
- 문서 간 연결 유지
- 프로젝트 전체의 일관성 유지
- 인덱스 최신화
- 품질 기준 준수

---

# 3. 핵심 원칙

## 3.1 정확성을 최우선으로 한다.

잘못된 정보를 작성하지 않는다.

확실하지 않은 내용은 추측하지 않는다.

---

## 3.2 실무 중심으로 작성한다.

단순한 정의만 작성하지 않는다.

다음을 함께 설명한다.

- 왜 사용하는가
- 언제 사용하는가
- 언제 사용하면 안 되는가
- 실무에서는 어떻게 사용하는가

---

## 3.3 운영 환경을 고려한다.

가능한 경우 다음 내용을 포함한다.

- 운영 중 발생 가능한 문제
- 장애 사례
- 성능 이슈
- 메모리 이슈
- 병목 현상
- 운영 경험

---

## 3.4 면접을 고려한다.

모든 문서는 기술 면접 준비에 도움이 되어야 한다.

단순한 사용법보다

"왜 그렇게 동작하는가"

를 설명한다.

---

## 3.5 장기 유지보수를 고려한다.

현재 문서 하나만 생각하지 않는다.

300개 이상의 문서가 생성되어도 유지될 수 있도록 작성한다.

---

# 4. 품질 기준

프로젝트의 기준 문서는

**001. Java Architecture**

이다.

새로운 문서는 최소한 다음 수준 이상의 품질을 유지해야 한다.

- 기술적 깊이
- 설명의 명확성
- 실무 활용성
- 운영 환경 고려
- 성능 분석
- 기술 면접 활용도

# 6. 문서 생성 원칙

문서를 작성할 때는 다음 순서를 따른다.

1. 기존 문서 확인
2. 중복 여부 확인
3. 문서 생성
4. 자가 검토
5. 인덱스 갱신

---

# 7. 문서 중복 금지

이미 존재하는 내용을 다시 작성하지 않는다.

주제가 겹치는 경우에는

- 기존 문서를 보강하거나
- 관련 문서를 링크한다.

---

# 8. 저장소 구조 준수

문서는 반드시 지정된 폴더에 생성한다.

임의의 폴더를 생성하지 않는다.

문서의 위치는 프로젝트 구조를 따른다.

## 8.1 사용자 지정 경로 강제

사용자가 문서 생성 경로를 명시한 경우 해당 경로를 최우선으로 따른다.

사용자의 사전 승인을 받지 않고 다음 항목을 다른 경로에 생성하지 않는다.

- 설계 문서
- 구현 계획 문서
- 작업 메모
- 임시 문서
- 보조 산출물

프로젝트 규칙상 인덱스처럼 반드시 수정해야 하는 기존 파일은 갱신할 수 있지만,
새로운 파일이나 폴더는 사용자가 지정한 경로 밖에 생성하지 않는다.

도구 또는 작업 절차가 별도 경로의 문서 생성을 권장하더라도 이 규칙을 우선한다.

---

# 9. 인덱스 관리

문서를 생성하거나 수정한 경우 반드시 다음 파일을 함께 갱신한다.

- PROBLEM-INDEX.md
- HANDBOOK-INDEX.md

두 파일은 항상 최신 상태를 유지해야 한다.

---

# 10. 기존 문서 존중

기존 문서를 임의로 삭제하거나 대규모 수정하지 않는다.

기존 내용을 변경해야 하는 경우에는

- 기존 내용을 유지하면서 개선하거나
- 필요한 내용을 추가한다.

---

# 11. 금지 사항

다음 행위는 금지한다.

- 중복 문서 생성
- 사실이 아닌 내용 작성
- 근거 없는 추측
- 프로젝트 구조 변경
- 기존 문서 삭제
- 인덱스 미갱신
- 품질 기준 이하의 문서 작성
