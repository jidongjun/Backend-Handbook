# Backend Interview Bible Codex 프롬프트 모음

## 1. 최초 실행 프롬프트

프로젝트를 처음 열었을 때 한 번만 입력한다.

```text
현재 디렉터리는 Backend Interview Bible 프로젝트 루트다.

작업을 시작하기 전에 반드시 다음 파일을 읽어라.

- README.md
- AGENTS.md
- PROBLEM-INDEX.md

이후 모든 작업에서는 AGENTS.md의 규칙을 최우선으로 따른다.

반드시 다음 규칙을 지켜라.

1. 프로젝트 루트 밖의 파일은 읽거나 수정하지 않는다.
2. 기존 문서를 임의로 삭제하거나 덮어쓰지 않는다.
3. PROBLEM-INDEX.md의 번호, 주제, 상태를 기준으로 작업한다.
4. 한 번의 요청에서는 하나의 주제 문서만 생성한다.
5. 생성 문서는 한국어로 작성하되 일반적인 기술 용어는 영어로 유지한다.
6. 모든 문서는 UTF-8 Markdown 형식으로 작성한다.
7. 필요한 경우 Mermaid 다이어그램을 포함한다.
8. 관련 문서가 실제로 존재할 때만 Obsidian Wiki Link를 추가한다.
9. 문서 생성 전 같은 번호의 파일이 존재하는지 확인한다.
10. 기존 파일이 있다면 새로 생성하거나 덮어쓰지 말고 작업을 중단한다.
11. 문서 생성 후 PROBLEM-INDEX.md에서 해당 번호의 상태만 ⬜에서 로 변경한다.
12. 다른 번호의 상태, 순서, 주제는 수정하지 않는다.
13. 작업 완료 후 생성한 파일, 수정한 파일, 검증 결과를 간단히 보고한다.

지금은 문서를 생성하지 마라.

README.md, AGENTS.md, PROBLEM-INDEX.md와 프로젝트 디렉터리 구조를 확인한 뒤 다음 내용만 보고하라.

- 이해한 작업 방식
- 번호별 저장 폴더 규칙
- 발견한 파일 또는 규칙 충돌
- 작업을 시작할 수 있는 상태인지 여부
```

## 2. 번호 직접 입력 프롬프트

특정 번호의 문서를 만들고 싶을 때 사용한다.

아래의 `031` 부분만 원하는 번호로 바꾼다.

```text
PROBLEM-INDEX.md의 031번 주제를 생성해라.

작업 전에 README.md, AGENTS.md, PROBLEM-INDEX.md를 다시 확인하고 AGENTS.md의 규칙을 모두 적용해라.

작업 순서:

1. PROBLEM-INDEX.md에서 031번의 주제, 상태, 분류를 확인한다.
2. 번호와 주제에 맞는 저장 폴더와 파일명을 결정한다.
3. 동일한 번호 또는 동일한 파일명의 문서가 존재하는지 확인한다.
4. 파일이 이미 존재하면 덮어쓰지 말고 작업을 중단한 뒤 기존 파일 경로를 보고한다.
5. 파일이 없으면 031번 문서 하나만 생성한다.
6. AGENTS.md에 정의된 문서 템플릿을 빠짐없이 적용한다.
7. 기술 설명은 개념, 등장 배경, 내부 동작, 장단점, 성능, 실무 사례 순서가 자연스럽게 이어지도록 작성한다.
8. Java 예제는 Java 21을 기준으로 작성한다.
9. Spring 예제가 필요한 경우 Spring Boot 3.x를 기준으로 작성한다.
10. 코드가 본문의 설명과 일치하는지 확인한다.
11. 관련 문서가 실제로 존재할 때만 Obsidian Wiki Link를 추가한다.
12. 유용한 경우 Mermaid 다이어그램을 포함한다.
13. 기술적 오류, Mermaid 문법, Markdown 구조를 자체 검토한다.
14. 생성이 완료되면 PROBLEM-INDEX.md에서 031번의 상태만 ⬜에서 로 변경한다.
15. 다른 번호와 파일은 수정하지 않는다.

완료 후 다음 내용을 보고하라.

- 생성한 문서 경로
- 수정한 파일
- 문서 번호와 주제
- 자체 검증 결과
- 추가 검토가 필요한 부분
```

### 간단 명령

Codex가 번호 명령을 안정적으로 처리하도록 설정된 후에는 아래처럼 짧게 입력할 수 있다.

```text
031
```

또는:

```text
031번 생성
```

## 3. PROBLEM-INDEX 확인 후 다음 문서 생성 프롬프트

번호를 직접 고르지 않고 순서대로 생성할 때 사용한다.

```text
README.md, AGENTS.md, PROBLEM-INDEX.md를 읽어라.

PROBLEM-INDEX.md에서 상태가 ⬜인 항목 중 번호가 가장 빠른 주제 하나를 찾아 해당 문서만 생성해라.

작업 순서:

1. PROBLEM-INDEX.md 전체를 확인한다.
2. 상태가 ⬜인 항목 중 번호가 가장 빠른 항목을 선택한다.
3. 선택한 번호, 주제, 분류, 현재 상태를 확인한다.
4. AGENTS.md의 폴더 매핑 규칙에 따라 저장 위치를 결정한다.
5. 동일한 번호나 파일명의 기존 문서가 있는지 확인한다.
6. 파일이 이미 존재하면 덮어쓰지 않는다.
7. 기존 파일과 PROBLEM-INDEX.md의 상태가 불일치하면 새 문서를 생성하지 말고 문제를 보고한다.
8. 문제가 없다면 선택된 주제 문서 하나만 생성한다.
9. AGENTS.md의 문서 템플릿과 품질 기준을 모두 적용한다.
10. Java 21 및 Spring Boot 3.x 기준으로 예제를 작성한다.
11. 필요한 경우 Mermaid를 포함한다.
12. 실제로 존재하는 문서에 대해서만 Obsidian Wiki Link를 추가한다.
13. 기술적 정확성, 코드, Markdown, Mermaid 문법을 자체 검토한다.
14. 생성에 성공한 경우 선택한 항목의 상태만 ⬜에서 로 변경한다.
15. 다음 번호의 문서는 생성하지 않는다.
16. 다른 상태와 주제, 순서는 수정하지 않는다.

완료 후 다음 내용을 보고하라.

- 선택한 번호
- 선택한 주제
- 생성한 파일 경로
- 수정한 파일
- 상태 변경 결과
- 검증 결과
```

### 간단 명령

설정이 안정적으로 적용된 후에는 아래 명령만 사용한다.

```text
next
```

# 추가 권장 프롬프트

## 문서 자체 검토

```text
방금 생성한 문서를 다시 검토해라.

검토 기준:

- 기술적 오류
- Java 21 기준의 정확성
- Spring Boot 3.x 기준의 정확성
- 내부 동작 설명의 깊이
- 코드의 문법 및 실행 가능성
- 코드와 본문의 일치 여부
- 잘못된 성능 설명
- 현실성이 부족한 실무 사례
- 면접 질문과 답변의 품질
- 꼬리 질문의 자연스러운 연결
- Senior-Level Answer의 구체성
- Mermaid 문법
- 존재하지 않는 Obsidian Wiki Link
- 중복되거나 불필요하게 긴 설명
- 참고 자료의 신뢰성

발견한 문제는 현재 문서에 직접 수정해라.

다른 주제 문서와 PROBLEM-INDEX.md의 다른 항목은 수정하지 마라.

PROBLEM-INDEX.md의 현재 상태는 로 유지해라.

완료 후 수정한 항목과 아직 확실하지 않은 부분을 보고하라.
```

---

## ChatGPT 리뷰 반영

```text
아래는 ChatGPT가 현재 문서를 검토한 결과다.

[여기에 ChatGPT 리뷰 내용을 붙여 넣는다]

위 리뷰를 현재 문서에 반영해라.

규칙:

1. 리뷰 내용을 무조건 적용하지 말고 기술적으로 타당한지 확인한다.
2. 명백한 기술 오류를 가장 먼저 수정한다.
3. 기존 문서의 좋은 설명과 구조는 유지한다.
4. 부족한 내부 동작, 실무 사례, 성능 관점을 보완한다.
5. 코드와 본문의 설명이 일치하도록 수정한다.
6. Java 21 및 Spring Boot 3.x 기준을 유지한다.
7. 중복되는 설명은 정리한다.
8. Mermaid와 Wiki Link를 다시 검증한다.
9. 다른 문서는 수정하지 않는다.
10. PROBLEM-INDEX.md 상태는 로 유지한다.

완료 후 리뷰 반영 내역과 제외한 의견이 있다면 그 이유를 보고하라.
```

---

## 최종 완료 상태 변경

```text
현재 문서의 작성과 외부 리뷰가 완료되었다.

다음 내용을 최종 검증해라.

1. 문서 파일이 실제로 존재하는가.
2. 파일 번호가 PROBLEM-INDEX.md의 번호와 일치하는가.
3. 파일명이 주제와 일치하는가.
4. 올바른 폴더에 저장되어 있는가.
5. 필수 문서 섹션이 빠지지 않았는가.
6. 코드 블록과 Mermaid 문법에 문제가 없는가.
7. 존재하지 않는 Wiki Link가 없는가.
8. 미해결 기술 오류가 없는가.

모든 검증을 통과한 경우에만 PROBLEM-INDEX.md에서 해당 번호의 상태를 에서 로 변경해라.

해당 번호 이외의 상태, 문서 본문, 다른 파일은 수정하지 마라.

검증에 실패하면 상태를 변경하지 말고 실패 항목을 보고하라.
```
